## 1. システム構成概要

| 項目 | 内容 |
|---|---|
| サーバー | Google Cloud Platform — Compute Engine (e2-micro) |
| ゾーン | us-central1-a |
| OS | Debian 12 |
| インストール先 | `/opt/KAGARIHI_bookkeeping` |
| 実行ユーザー | `botuser`（ログイン不可のシステムユーザー） |
| リポジトリ | GitHub: `privatemkn4agtkt-source/KAGARIHI_bookkeeping` |

### 稼働サービス

| サービス名 | 内容 | プロセス |
|---|---|---|
| `bookkeeping-bot` | Discord BOT 本体 | `python main.py` |

```
/opt/KAGARIHI_bookkeeping/
├── main.py               # Discord BOT 本体
├── dashboard.py          # Webダッシュボード
├── bookkeeping.db        # SQLiteデータベース（取引データ）
├── .env                  # 環境変数（シークレット情報）
├── requirements.txt      # Pythonパッケージ一覧
├── venv/                 # Python仮想環境
└── deploy/               # デプロイ用スクリプト・設定ファイル

    ├── gcp_server_setup.sh
    ├── update.sh
    ├── bookkeeping-bot.service
    ├── bookkeeping-dashboard.service
    └── nginx.conf.template
```

## 2. 初回セットアップ手順

### 手順A：GCP VM の作成（ローカルPCで実行）

**前提条件：**
- Google Cloud SDK (`gcloud`) がインストール済み
- `gcloud auth login` および `gcloud config set project PROJECT_ID` 実施済み

```bash
# リポジトリをクローン後、以下を実行
bash deploy/gcp_vm_create.sh
```

実行後に表示される「外部IP」をメモしておく。

### 手順B：ドメインのDNS設定

取得した外部IPに対してドメインのDNS Aレコードを設定する。
（設定後、DNSの浸透まで最大24時間かかる場合がある）

### 手順C：VMへのSSHログイン

```bash
gcloud compute ssh kagarihi-bot --zone=us-central1-a
```

### 手順D：VM上でセットアップスクリプトを実行

```bash
# GitHub から直接実行する場合
curl -fsSL https://raw.githubusercontent.com/privatemkn4agtkt-source/KAGARIHI_bookkeeping/main/deploy/gcp_server_setup.sh | bash

# または git clone してから実行
git clone https://github.com/privatemkn4agtkt-source/KAGARIHI_bookkeeping.git
cd KAGARIHI_bookkeeping
bash deploy/gcp_server_setup.sh
```

スクリプト実行中に以下の入力を求められる：

| 入力項目 | 説明 |
|---|---|
| DISCORD_TOKEN | Discord Developer Portal の Bot Token |
| CLIENT_ID | Discord Developer Portal の Application ID |
| GUILD_ID | サーバーID（省略可） |
| DISCORD_CLIENT_SECRET | OAuth2 シークレット |
| ドメイン名 | ダッシュボードのドメイン（例：dashboard.example.com） |
| ALLOWED_DISCORD_IDS | ダッシュボードにアクセス可能なDiscord IDのカンマ区切りリスト |
| メールアドレス | Let's Encrypt 証明書更新通知用 |

## 3. 日常運用：コード更新・BOT再起動

### 通常のアップデート（推奨）

GitHubにプッシュ済みのコードをサーバーに反映する手順。

**1. VMにSSHログイン**

```bash
gcloud compute ssh kagarihi-bot --zone=us-central1-a
```

**2. アップデートスクリプトを実行**

```bash
bash /opt/KAGARIHI_bookkeeping/deploy/update.sh
```

このスクリプトは以下を自動で行う：

1. `git pull` でコード更新
2. pip パッケージ更新（`requirements.txt` に変更がある場合も対応）
3. systemd サービスファイルの反映（`daemon-reload`）
4. `bookkeeping-bot` 再起動
5. `bookkeeping-dashboard` 再起動

### BOTのみ手動再起動

```bash
sudo systemctl restart bookkeeping-bot
```

### ダッシュボードのみ手動再起動

```bash
sudo systemctl restart bookkeeping-dashboard
```

### ダッシュボードのリアルタイムログ

```bash

```

```bash
# 直近100行
sudo journalctl -u bookkeeping-bot -n 100

# 今日のログ
sudo journalctl -u bookkeeping-bot --since today

# 特定日時以降のログ
```

```bash
# エラーログ
```

## 6. トラブルシューティング

### BOTがオフラインになっている

```bash
# 状態確認
sudo systemctl status bookkeeping-bot

# ログでエラー内容を確認
sudo journalctl -u bookkeeping-bot -n 50

# 再起動
sudo systemctl restart bookkeeping-bot
```

**よくある原因：**
- Discord Token が無効（Developer Portal で再発行し `.env` を更新）
- ネットワーク一時障害（自動的に再起動されるが、10秒待っても復旧しない場合は手動再起動）
- コードのバグ（ログでエラー内容を特定する）

### ダッシュボードにアクセスできない

```bash
# ダッシュボード状態確認
sudo systemctl status bookkeeping-dashboard

# Nginx状態確認
sudo systemctl status nginx

# SSL証明書の有効期限確認
sudo certbot certificates
```

**よくある原因：**
- SSL証明書の期限切れ（→「9. SSL証明書の更新」参照）
- ダッシュボードサービスが停止している
- Nginxが停止している

### git pull でコンフリクトが発生した

```bash
# VM上で手動対応
cd /opt/KAGARIHI_bookkeeping
sudo -u botuser git status
sudo -u botuser git stash   # ローカル変更を一時退避
sudo -u botuser git pull
```

### ストレージ容量が満タンになった

#### 1. 現状確認

```bash
# ディスク使用量の確認
df -h

# 大きいディレクトリを特定
sudo du -sh /var/log /opt/KAGARIHI_bookkeeping /tmp /var/cache/apt
```

#### 2. systemd ジャーナルログの削除（最も効果的）

journald のログはデフォルトで無制限に蓄積される。

```bash
# 現在のジャーナルサイズを確認
sudo journalctl --disk-usage

# 2日以上前のログを削除
sudo journalctl --vacuum-time=2d

# または 500MB 以下になるまで削除
sudo journalctl --vacuum-size=500M
```

#### 3. apt キャッシュの削除

```bash
sudo apt-get clean
```

#### 4. VM 上の一時DBバックアップをローカルへ退避してから削除

VM 上の `bookkeeping_*.db` はローカルPCに取得済みであれば削除して構わない。
**必ずローカルへのダウンロードを先に行うこと**（→「7. バックアップ方法」参照）。

```bash
# ローカルPC側で先にダウンロード
gcloud compute scp kagarihi-bot:/opt/KAGARIHI_bookkeeping/bookkeeping.db \
  ~/bookkeeping_backup/bookkeeping_$(date +%Y%m%d).db \
  --zone=us-central1-a

# ダウンロード確認後、VM 上のホームディレクトリの一時バックアップを削除
gcloud compute ssh kagarihi-bot --zone=us-central1-a -- "ls -lh ~/bookkeeping_*.db"
gcloud compute ssh kagarihi-bot --zone=us-central1-a -- "rm ~/bookkeeping_*.db"
```

#### 5. Nginx ログのリセット

```bash
# ログサイズを確認
sudo du -sh /var/log/nginx/

# ログをクリア（Nginx が新しいファイルを作成する）
sudo truncate -s 0 /var/log/nginx/kagarihi_access.log
sudo truncate -s 0 /var/log/nginx/kagarihi_error.log
```

#### 6. 容量回復後にサービスを再起動

容量不足でサービスが停止していた場合：

```bash
sudo systemctl restart bookkeeping-bot bookkeeping-dashboard
sudo systemctl status bookkeeping-bot bookkeeping-dashboard --no-pager
```

#### 今後の対策

ジャーナルログの上限を設定して再発を防ぐ：

```bash
# /etc/systemd/journald.conf を編集
sudo nano /etc/systemd/journald.conf
# SystemMaxUse=200M を追記

# 設定反映
sudo systemctl restart systemd-journald
```

### BOTが起動直後にクラッシュを繰り返す

```bash
# 直近のエラーを確認
sudo journalctl -u bookkeeping-bot -n 30 --no-pager

# 自動再起動を一時停止して調査
sudo systemctl stop bookkeeping-bot

# 手動でBOTを起動してエラーを直接確認
sudo -u botuser /opt/KAGARIHI_bookkeeping/venv/bin/python /opt/KAGARIHI_bookkeeping/main.py
```

## 7. バックアップ方法

**基本方針：取引履歴（DBファイル）はローカルPCに永続保管する。**
GCP VM はいつでも削除・再作成される可能性があるため、`bookkeeping.db` の正本はローカルPC側で管理すること。VM 上のファイルはあくまで稼働中の作業コピーと位置づける。

### Excel ファイルでダウンロード（推奨）

取引データを書式付き Excel ファイルとしてエクスポートし、ローカルに保管する。

**ステップ 1：VM 上で Excel ファイルを生成**

```bash
gcloud compute ssh kagarihi-bot --zone=us-central1-a -- \
  "sudo -u botuser /opt/KAGARIHI_bookkeeping/venv/bin/python \
  /opt/KAGARIHI_bookkeeping/deploy/export_excel.py"
```

VM 上の `/opt/KAGARIHI_bookkeeping/export/会計データ_YYYYMMDD.xlsx` に出力される。

**ステップ 2：ローカルPCへダウンロード**

```bash
# 保存先フォルダを作成（初回のみ）
mkdir -p ~/bookkeeping_backup

# Excel ファイルをダウンロード
gcloud compute scp \
  "kagarihi-bot:/opt/KAGARIHI_bookkeeping/export/会計データ_$(date +%Y%m%d).xlsx" \
  ~/bookkeeping_backup/ \
  --zone=us-central1-a
```

**Excel ファイルの内容（シート構成）：**

| シート名 | 内容 |
|---|---|
| 仕訳帳 | 全取引（収益＝緑・費用＝橙で色分け、フィルター付き） |
| 立替精算 | メンバーの立替記録（精算済みはグレー表示） |
| グッズ取引 | グッズの仕入・販売履歴 |
| グッズ在庫 | 現在の在庫数・在庫評価額 |
| 勘定科目 | 使用中の勘定科目一覧（種別ごとに色分け） |

### 定期ダウンロードの自動化（推奨）

**ローカルPCの crontab** で毎週自動取得：

```bash
crontab -e

# 毎週月曜 午前9時に Excel エクスポート＋ダウンロードする例
0 9 * * 1 gcloud compute ssh kagarihi-bot --zone=us-central1-a -- \
  "sudo -u botuser /opt/KAGARIHI_bookkeeping/venv/bin/python \
  /opt/KAGARIHI_bookkeeping/deploy/export_excel.py" && \
  gcloud compute scp \
  "kagarihi-bot:/opt/KAGARIHI_bookkeeping/export/会計データ_$(date +\%Y\%m\%d).xlsx" \
  ~/bookkeeping_backup/ --zone=us-central1-a
```

ダウンロードしたファイルはローカルに蓄積し続けて問題ない（1ファイルあたり数MB程度）。

### DB ファイルのダウンロード（任意）

Excel ではなく SQLite ファイルのまま保管したい場合：

```bash
gcloud compute scp kagarihi-bot:/opt/KAGARIHI_bookkeeping/bookkeeping.db \
  ~/bookkeeping_backup/bookkeeping_$(date +%Y%m%d).db \
  --zone=us-central1-a
```

### .env のバックアップ

```bash
# .env はシークレット情報を含むため、安全な場所に保管
sudo cat /opt/KAGARIHI_bookkeeping/.env
```

**注意：** `.env` の内容はGitにコミットしないこと。

## 9. SSL証明書の更新

Let's Encrypt の証明書は **90日間有効** で、systemd タイマーにより **自動更新** される。

Nginx の設定（`deploy/nginx.conf.template`）にはポート80で `/.well-known/acme-challenge/` を直接返す専用ルートが設定されており、更新時に ACME チャレンジが HTTPS リダイレクトに巻き込まれない。`certbot --nginx` プラグインが証明書更新後に Nginx を自動リロードするため、**ダウンタイムなしで更新される**。

### 自動更新の状態確認

```bash
sudo systemctl status certbot.timer
```

### 手動で証明書を更新（期限切れ時など）

```bash
sudo certbot renew
sudo systemctl reload nginx
```

### 証明書の有効期限確認

```bash
sudo certbot certificates
```

### 自動更新が失敗するパターン

| 原因 | 確認・対処 |
|---|---|
| ドメインの DNS が現在のサーバー IP を向いていない | DNS の A レコードを確認・修正 |
| GCP のファイアウォールでポート 80 が閉じられた | GCP コンソールで `allow-http` ルールを確認 |
| ディスクの空き容量不足 | `df -h` で確認し不要ファイルを削除 |

更新失敗は Let's Encrypt からメール通知が届くため、`.env` 設定時に入力したメールアドレスを定期的に確認すること。
